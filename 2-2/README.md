두 AI로 HTML 만들고 테스트하기

1. 미션 소개
기획서에 정리한 구상이 실제 화면으로 구현되면, 글로만 읽을 때는 알기 어려웠던 차이가 드러납니다. 같은 정보를 담더라도 목록으로 나열하거나 주제별로 묶는 등 구성 방식에 따라 내용을 찾고 읽는 경험은 달라집니다. 같은 기획서를 전달해도 AI마다 화면 구성이나 기능 구현 방식은 달라질 수 있습니다.

두 결과 중 어느 쪽을 선택할지 판단하려면 비교할 기준이 필요합니다. 화면의 인상과 함께, 기획서에서 정한 정보를 찾기 쉬운지, 링크와 버튼이 기대한 대로 동작하는지 확인해야 합니다. 두 페이지에 같은 작업을 수행하면 각각의 장점과 부족한 부분을 구체적으로 비교할 수 있습니다.

테스트 조건을 바꾸면 평소에는 드러나지 않던 문제도 발견할 수 있습니다. 넓은 화면에서는 잘 보이던 내용이 좁은 화면에서는 가려지거나, 입력값이 없을 때 예상하지 못한 결과가 표시될 수 있습니다. 예상 결과와 실제 결과를 구분해 기록하면 무엇이 제대로 구현되었고 어느 부분을 수정해야 하는지 설명할 수 있습니다.

이번 미션에서는 'AI와 함께 HTML 페이지 기획서 작성하기'에서 작성한 기획서를 두 AI에게 동일하게 전달해 각각 HTML 페이지를 제작합니다. 두 결과를 같은 방법으로 테스트한 뒤 하나를 선택하고, 선택 근거와 테스트 결과를 기록합니다. 선택한 HTML과 제작검증기록은 다음 미션인 '테스트하며 고치고 사용자 피드백 반영하기'에서 활용합니다.

2. 최종 결과물
다음 2가지 산출물을 제출한다. (첨부된 제작검증기록 양식을 활용할 수 있다.)

HTML 파일 1개
두 AI의 결과 중 선택한 HTML 파일이다.
페이지의 내용에 맞게 파일 이름을 정하고, 페이지_v1.html처럼 버전을 표시한다.
**제작검증기록.md**
두 AI의 서비스·모델 이름, 전달한 요청, 각 결과의 비교 내용과 선택 근거
선택한 HTML의 테스트 결과 3건
선택하지 않은 HTML의 결과는 설명이나 화면 캡처로 남기고, 해당 HTML 파일은 제출하지 않는다.
제작검증기록은 화면 캡처를 포함한 문서 파일이나 PDF로 제출할 수 있다. 이전 미션에서 작성한 기획서.md도 평가 참고 자료로 함께 첨부한다.

3. 과제 목표
이 과제를 마친 후, 학습자는 다음을 수행할 수 있어야 한다.

같은 기획서로 제작한 두 AI의 결과를 비교하고, 선택 근거를 설명할 수 있다.
AI가 생성한 HTML을 브라우저에서 열고, 완료 기준에 따라 동작을 테스트할 수 있다.
테스트 내용, 예상 결과, 실제 결과를 구분하여 기록할 수 있다.
화면 너비, 입력값, 인쇄 등 조건을 변경하여 테스트할 수 있다.

7. 제약 사항
HTML은 파일 1개로 구성한다. CSS와 필요한 JavaScript를 같은 파일에 포함하고, 평가자가 브라우저에서 열어 기획서의 필수 기능을 확인할 수 있도록 한다.
로그인, API 키, 서버가 필요한 기능과 챗봇·AI 기능은 추가 기능으로 분류하고, 이번 제작 요청에서는 제외한다.
사진·글·글꼴·라이브러리 등 외부 자료는 사용 권한을 확인한 뒤 활용한다. 사진은 로컬 파일 대신 https://로 시작하는 인터넷 주소로 삽입한다. 인터넷 주소로 불러오는 자료는 별도로 첨부하지 않으며, 다른 컴퓨터에서도 정상적으로 표시되는지 테스트한다.
두 AI에 동일한 기획서와 요청을 전달한다. 한쪽에만 추가 요청을 전달하지 않는다.
제작과 기록 정리에 AI를 자유롭게 활용하되, 선택 근거와 테스트 결과는 직접 판단하고 관찰한 내용으로 작성한다.
