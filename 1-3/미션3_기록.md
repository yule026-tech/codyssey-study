# 미션 3 기록

## 1. 기획서 기준 독립 점검

받은 의견을 판단하기 위한 기준으로, 기획서의 완성 기준별 테스트를 정리했다. 아래 내용은 직접 사용해 본 결과와 HTML 코드 확인 내용을 구분해 기록했다. HTML 원본은 수정하지 않았다.

| 기획서의 완성 기준 | 확인 행동 | 확인 결과 |
|---|---|---|
| 영화가 한 칸에만 있고 옮긴 칸에 남는다 | 영화를 선택해 등급 버튼 클릭, 카드를 드래그해 등급 이동 | 두 방식 모두 정상적으로 이동했다(직접 테스트). |
| 제목을 입력하면 새 영화 카드가 생긴다 | 영화 제목 입력 → '추가' 클릭 | 영화 카드 추가 기능이 정상 작동했다(직접 테스트). |
| 같은 브라우저에서 같은 파일을 다시 열어도 영화와 등급이 남는다 | 영화를 분류하고 새로고침 | 분류 결과가 사라지고 처음 상태로 돌아왔다(직접 테스트). 같은 파일을 닫았다 다시 여는 상황도 별도 확인하면 좋다. |
| 좁은 화면에서도 오른쪽이 잘리지 않고 볼 수 있다 | 브라우저 창을 좁혀 보기 및 휴대폰으로 열기 | PC 화면을 줄인 모습은 캡처로 남겼고, 휴대폰에서는 오른쪽이 잘리고 아래 분류표도 제대로 보이지 않았다고 확인했다(직접 테스트). HTML에는 960px 고정 너비가 지정되어 있다(코드 확인). |
| ‘처음으로’를 누르면 처음 8개가 모두 미분류로 돌아간다 | 영화 추가 후 '처음으로' 클릭 | 초기화가 정상 동작했다(직접 테스트). 추가 목록 삭제는 HTML의 초기화 코드로도 확인했다. |
| 외부 파일이나 로그인 없이 HTML 한 장으로 열린다 | HTML 파일 직접 열기, HTML 코드 확인 | 파일이 브라우저에서 열렸으며, 스타일과 스크립트가 HTML 안에 포함되어 있다. |

## 2. 받은 의견 검증 및 판단

| 받은 의견 | 직접 해 본 결과 | 반영 / 보류 / 되묻기 | 이유 (되묻기라면 물을 질문) |
|---|---|---|---|
| **AI 1.** 저장 기능이 없어 다시 열면 미분류로 돌아간다 | 영화 등급을 옮긴 뒤 새로고침하자 처음 상태로 돌아왔다. HTML 코드에도 배치를 저장하거나 읽어 오는 처리가 없다. | **반영** | 기획서에서 같은 브라우저로 다시 열어도 영화와 등급이 남아야 한다고 명시했다. |
| **AI 2.** '처음으로'를 눌러도 추가 영화가 남는다 | '처음으로' 버튼은 직접 테스트에서 정상 동작했다. 코드에서도 처음 8편만 있는 상태로 다시 만든다. | **보류** | 직접 확인한 결과 AI의 설명과 다르며 초기화는 기획서대로 동작한다. |
| **AI 3.** 빈 제목이 추가되므로 기획서를 어긴다 | HTML 코드를 보면 빈 제목인지 확인하지 않고 카드를 추가한다. 빈 카드 생성은 코드상 예상되며, 실제 빈 제목 테스트 결과를 한 번 더 확인해 기록하면 좋다. | **반영** | 빈 카드를 막는 개선은 유용하다. 다만 기획서에 빈 제목 금지 조건은 없으므로 '기획서 위반'이라는 AI의 근거는 틀렸다. |
| **동료 장점 1.** 등급마다 색이 달라 구별하기 쉽다 | S·A·B·C 등급 배지가 서로 다른 색으로 표시된다. | **반영(장점 유지)** | 네 가지 등급을 쉽게 구별하게 해 주므로 현재 방식을 유지하면 좋다. |
| **동료 장점 2.** '8편 중 3편 나눔' 같은 진행 표시가 좋다 | 화면에서 전체/분류 수 표시가 확인되며 등급에 옮길 때 갱신되도록 구현되어 있다. | **반영(장점 유지)** | 현재 분류한 수를 확인할 수 있어 사용에 도움이 된다. |
| **동료 장점 3.** 끌어 놓을 때 칸 색이 바뀐다 | 드래그 이동은 직접 테스트에서 정상 작동했다. 드래그 중 영역 강조는 HTML 스타일과 이벤트 코드에서 확인된다. | **반영(장점 유지)** | 카드를 놓을 위치를 알아보기 쉽게 하므로 유지할 만하다. |
| **동료 1.** 휴대폰으로 열면 불편하다 | 휴대폰에서 열었을 때 화면이 잘리고 아래의 분류표가 제대로 나타나지 않았다(직접 테스트). 코드상 화면은 960px 고정 폭이다. | **반영** | 기획서가 좁은 화면에서도 오른쪽이 잘리지 않아야 한다고 명시한다. |
| **동료 2.** 카드 옮기는 게 처음에 헷갈린다 | 카드를 클릭한 뒤 등급 글자를 누르면 이동하며, 화면 위에 사용 방법 안내가 표시된다. 무엇이 헷갈렸는지는 이 의견만으로 특정할 수 없다. | **되묻기** | '카드 선택 방법, 등급을 누르는 순서, 드래그 중 어느 부분이 헷갈렸나요?' |
| **동료 3.** 아래의 미분류 카드를 맨 위 S칸까지 드래그하기 불편하다 | 영화 목록이 S·A·B·C 칸 아래에 위치한다. 드래그 자체는 정상 작동했으며, 긴 이동이 불편한지는 사용자마다 다를 수 있다. | **보류** | 직접 테스트에서는 드래그가 정상 작동했고, 긴 이동이 실제로 불편했는지는 추가 확인이 필요하다. 다만 목록을 위·옆으로 옮기는 것은 기획서의 화면 배치와 충돌하므로, 위치를 바꾸기보다 '카드 선택 → 등급 클릭' 방식을 더 잘 안내하는 방안을 우선 제안한다. |
| **동료 4.** 카드 색이 칙칙하다 | 영화 카드는 회색 계열의 그라데이션으로 표시된다. | **보류** | 색에 대한 취향에 가까우며 구체적으로 읽기 어렵거나 구분되지 않는 문제는 제시되지 않았다. |
| **동료 5.** 영화 포스터가 있으면 좋겠다 | 현재 카드는 제목만 있는 형태다. | **보류** | 기획서에서는 포스터를 요구하지 않고 HTML 한 장으로 동작하도록 했다. 사진 추가가 꼭 필요한 수정이라고 판단하기 어렵다. |
| **동료 6.** C칸은 없어도 된다 | 화면에 S·A·B·C 네 칸이 있고 C에도 영화를 옮길 수 있다. | **보류** | S·A·B·C로 영화를 분류한다는 핵심 목적과 조건에 어긋나는 제안이다. |
| **동료 종합.** 큰 문제 없으니 PASS | 클릭·드래그·초기화는 동작하지만 저장과 좁은 화면이라는 완성 기준 미충족이 확인되었다. | **보류** | '큰 문제 없음'이라는 결론에는 동의하기 어렵다. PASS 여부는 미션의 평가 기준에 따라 다시 판단해야 한다. |

## 3. 아무도 말하지 않았는데 내가 찾은 것

- AI는 '이 세 가지 외에는 완성 기준을 잘 지킨다'고 했지만 **휴대폰에서 오른쪽이 잘리고 아래 분류표도 제대로 보이지 않는 문제**를 놓쳤다. 동료는 '휴대폰이 불편하다'고만 했지만, 직접 열어 보니 구체적인 증상을 확인할 수 있었다. 코드에는 960px 고정 폭이 지정되어 있다.
- HTML 코드를 보니 빈 제목을 막는 조건이 없다. **빈 제목으로 추가했을 때 실제 화면에 빈 카드가 생기는지** 추가 확인하면 좋겠다.
- 좋은 점: 카드를 선택해서 등급 글자를 누르는 방식과 드래그 방식이 모두 동작하고, 분류 개수가 즉시 갱신된다.

## 4. (선택) 코랩에서 함께 이야기하고 싶은 내용과 그 이유

- **빈 제목 의견의 근거:** 실제로 고칠 만한 불편은 맞지만 기획서 위반이라고 할 수는 없다. 다른 사람은 반영/보류를 어떻게 판단했는지 비교하고 싶다.
- **드래그 불편 해결:** 미분류 목록을 위로 옮기면 기획서 화면 구조와 부딪힌다. 배치를 유지하면서 더 편하게 만드는 방법을 비교하고 싶다.
- **AI 판단 검증:** AI가 초기화 기능을 잘못 지적한 이유와, 좁은 화면 문제를 놓친 이유를 확인 행동과 함께 이야기하고 싶다.

> 검증 환경 메모: 직접 Chrome 브라우저에서 HTML을 열어 주요 버튼과 카드 이동 기능을 테스트했고 새로고침 시 초기화되는 현상을 확인했다. 휴대폰에서도 열어 화면이 잘리는 현상을 확인했다. 일부 상세 동작과 원인은 HTML 코드도 함께 검토했다. 빈 제목 테스트 등 개별 세부 결과는 제출 전 다시 확인할 수 있다.
