## 두 AI 비교

- AI A (서비스·모델 이름): ChatGPT (세부 모델명 미확인)
- AI B (서비스·모델 이름): Claude (세부 모델명 미확인)
- 동일한 기획서와 함께 전달한 요청: 최종 기획서를 바탕으로 HTML·CSS·JavaScript가 포함된 단일 HTML 파일을 제작하고, 예시 데이터 없이 경험 추가·수정·삭제, 유형 필터, 상세 조회, 입력값 검증, STAR·면접 내용 입력, 브라우저 저장 기능을 구현하도록 요청하였다. 화면은 한국어로 구성하고 연보라·민트 포인트와 2열 카드형 디자인을 적용하도록 하였다. **두 서비스에 전송한 문구가 완전히 동일했는지는 채팅 원문으로 대조하지 못했다.**

- 선택한 결과물과 근거: 두 결과물의 기본 기능에 큰 차이가 없어서 디자인의 통일성과 사용 편의성을 중심으로 비교하였다. ChatGPT 버전은 부드러운 색상의 넓은 헤더, 간결한 카드 배치, 쉽게 찾을 수 있는 경험 추가·필터 버튼이 마음에 들어 최종 채택했다. 비교 표의 기능 설명은 두 HTML의 **코드에서 확인한 내용**이며, Claude 버전을 동일한 조건으로 직접 실행한 테스트 결과라고 단정하지 않는다.

## 수정 기록

### 수정 기록 1
- 발견한 문제: 실제 여러 활동을 입력한 뒤 상세 화면을 확인했을 때, 긴 STAR·활동 내용이 한꺼번에 보여 읽기 어려웠다. 진행 중인 코더스·코디세이 같은 활동도 종료일을 요구했고, 특정 활동을 제목으로 찾는 기능이 없었다. 기대한 결과는 필요한 내용만 펼치고, 진행 상태를 구분하고, 활동명으로 검색하는 것이었으나 기존 화면에서는 이를 할 수 없었다.
- AI에게 전달한 요청: “기존 디자인과 데이터 저장 기능은 유지하면서 활동명 검색, 진행 중/완료 상태와 종료일 미정 처리, 긴 활동·STAR 내용 접기·펼치기를 추가해 줘. HTML 전체를 새 버전으로 저장할 수 있게 만들어 줘.”
- 수정 후 테스트 결과: `커리어아카이브_v2_조회개선.html`로 저장한 뒤 활동명 검색, 진행 상태 표시·저장, 접기·펼치기를 테스트해 모두 정상 작동함을 확인했다. 기존 수정·삭제·저장 기능도 다시 확인해 정상 작동했다.
- 수정 이유: 활동이 많고 글이 길어질수록 원하는 경험을 찾기 어려우며, 진행 중인 활동을 실제 상태대로 기록할 수 없기 때문이다.

### 수정 기록 2
- 발견한 문제: 한 브라우저에서 입력한 경험을 다른 브라우저에서 같은 HTML로 열었을 때도 표시되기를 기대했으나, 실제로는 기존 데이터가 보이지 않았다. 평가자도 “다른 컴퓨터에서는 데이터가 안 보이나요? DB 연결은 안 된 건가요?”라고 질문했다.
- AI에게 전달한 요청: “브라우저마다 저장 데이터가 따로 있어 다른 브라우저에서 기존 경험이 보이지 않아. 서버 없이도 JSON 파일로 기록을 백업하고 다른 브라우저에서 가져올 수 있게 해 줘. 잘못된 파일을 검사하고 기존 기록을 덮어쓰기 전에 확인하도록 해 줘.”
- 수정 후 테스트 결과: `커리어아카이브_v3_백업복원.html`에서 JSON 다운로드, 다른 브라우저로 가져오기, 경험 목록 복원, 새로고침 후 기록 유지 등 **4개 항목을 직접 실행하여 모두 성공**했다. 기존 검색·저장 기능도 유지하도록 구현했다. 단, 자동 동기화나 서버 DB 연동을 구현한 것은 아니다.
- 수정 이유: 다른 브라우저나 컴퓨터를 이용할 때 기존 경험을 다시 작성해야 하는 불편을 줄이고, 중요한 활동 기록을 파일로 보관할 수 있도록 하기 위해서다.

### 수정 기록 3
- 발견한 문제: 기존 화면은 한 활동의 면접 예상 질문과 핵심 답변을 각각 하나의 큰 입력란에 작성하는 방식이었다. 여러 질문을 개별적으로 저장·관리하거나 무작위로 뽑아 연습하려고 했으나, 그런 기능이 없어 기록을 실전 연습에 활용하기 어려웠다.
- AI에게 전달한 요청: “한 활동에 면접 질문과 핵심 답변을 여러 세트 등록·수정·삭제할 수 있게 해 줘. 별도의 면접 연습 메뉴에서 활동명과 랜덤 질문을 보여 주고, 답변 보기 버튼으로 해당 핵심 답변을 확인하게 해 줘. 기존 질문 데이터와 v3 백업·복원 기능은 유지해 줘.”
- 수정 후 테스트 결과: `커리어아카이브_v4_면접연습.html`로 저장하여 질문 세트 관리와 랜덤 면접 연습 화면을 구현했고, JavaScript 문법 검사를 통과했다. 제작자가 이후 전체 체크리스트를 완료했다고 알려왔으나, 질문별 구체적인 실행 관찰 내용은 별도로 전달하지 않아 세부 동작을 임의로 서술하지 않았다. 이후 `커리어아카이브_v5_타임라인.html`에 활동별 기간을 표시하는 가로 막대형 타임라인을 추가했고, 통합형 v6와 비교한 후 **v5를 최종 선택**했다.
- 수정 이유: 면접 질문을 하나씩 나누어 관리하고 답변을 보기 전에 스스로 말해 볼 수 있어야 경험 기록을 실제 면접 준비에 효과적으로 활용할 수 있기 때문이다.

## 사용자 테스트

- 테스트 참여자와 요청한 작업: **2-2 과제 평가자**가 웹페이지의 데이터 보관 방식에 대해 질문했다. 다만 평가자에게 사용법을 설명하지 않은 채 특정 작업을 수행하도록 요청했는지, 실제 조작을 관찰했는지는 확인되지 않았다. 따라서 아래는 *평가자 질문을 통해 받은 피드백*에 관한 기록이다.
- 사용자의 행동과 질문: 평가자에게서 “다른 컴퓨터에서는 데이터가 안 보이는 건가요? DB 연결은 안 된 건가요?”라는 취지의 질문을 받았다. 평가자의 버튼 클릭, 화면 이동 등의 행동은 직접 관찰했다고 기록할 근거가 없다.
- 받은 피드백: 브라우저를 바꾸거나 다른 컴퓨터를 사용할 때 입력한 활동을 계속 볼 수 있는지 명확하지 않다는 점을 확인했다. 현재 데이터가 해당 브라우저의 `localStorage`에만 저장되어 있어 자동으로 공유되지 않는다는 한계가 드러났다.
- 반영 내용과 결과: JSON 백업·가져오기 기능을 추가했다. 제작자가 다른 브라우저에서 복원하는 과정을 포함한 4개 테스트를 직접 수행해 모두 정상 작동함을 확인했다. 이는 **수동 데이터 이동 기능**이며 DB 연결이나 자동 동기화는 아니다. 과제에서 요구하는 ‘다른 사용자 1명에게 작업만 제시한 뒤 행동을 관찰하는 테스트’까지 충족하려면, 실제로 수행한 사용자 테스트의 참여자·요청한 작업·관찰한 행동을 추가로 확인해 기록해야 한다.
