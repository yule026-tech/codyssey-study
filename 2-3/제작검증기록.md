**선택한 결과물과 근거:** 두 AI의 결과물을 비교했을 때 경험 추가·상세 보기·수정·삭제·저장 등 주요 기능에서 큰 차이는 없었다. 따라서 기능의 수보다 **디자인의 통일성, 첫 화면의 가독성, 사용 편의성**을 중심으로 선택하였다. ChatGPT 버전은 연보라·민트 그라데이션 헤더와 2열 카드가 조화롭게 구성되어 있고, 경험 목록과 필터·추가 버튼을 한눈에 파악하기 쉬웠다. 상세 화면도 필요한 내용을 섹션별로 확인할 수 있어 취업 준비용 개인 기록 페이지에 더 적합하다고 판단하여 **ChatGPT의 `커리어아카이브.html`을 최종 선택**하였다.

> 비교표는 **제출된 HTML 소스코드에서 확인한 구현과 디자인 구성**을 기준으로 작성했다. 브라우저 실행 결과는 선택한 ChatGPT 버전에서 제작자 본인이 수행한 3개 테스트를 기준으로 기록했다. Claude 버전의 실행 결과까지 동일하게 검증한 것은 아니다. 두 파일의 `localStorage` 키가 달라 저장된 경험 데이터가 서로 자동으로 공유되지 않는다.

## 수정 기록

> 2-2의 비교·테스트 기록은 위에 보존하고, 아래는 **2-3 시작 후의 개선 이력**이다. 확인한 사항과 아직 테스트하지 않은 사항을 구분한다.

### 수정 기록 1 — 활동 조회 편의성 개선 (`커리어아카이브.html` → `커리어아카이브_v2_조회개선.html`)

- **발견한 문제(테스트·예상·실제):** 실제 활동들을 입력하고 살펴보니 STAR·성과 등 긴 내용이 이어져 가독성이 떨어졌다. 완료된 경험과 진행 중인 경험을 구분하기 어려웠고, 종료일이 정해지지 않은 활동도 종료일을 요구했다. 활동명을 직접 검색하는 기능도 없었다. 예상했던 사용 방식은 긴 내용을 필요할 때만 펼쳐 보고, 현재 진행 상태를 표시하며, 제목으로 특정 활동을 빠르게 찾는 것이었다.
- **AI에게 전달한 요청(요지):** 기존 디자인과 저장 기능은 유지하면서 활동명 검색, 진행 중/완료 상태 표시 및 종료일 미정 선택, 긴 활동·성과·STAR·면접 내용 접기·펼치기를 추가하도록 요청했다.
- **수정 후 테스트 결과(제작자 직접 확인):** 활동명 검색, 진행 상태 표시 및 저장, 접기·펼치기, 기존 수정·삭제·저장 기능이 **모두 정상 동작함**을 확인했다.
- **수정 이유:** 내용이 많아질수록 읽고 싶은 정보를 찾기 어렵고, 진행 중인 활동을 실제 상태대로 기록할 수 없어 사용 편의성이 떨어지기 때문이다.

### 수정 기록 2 — 브라우저 간 백업·복원 기능 (`커리어아카이브_v2_조회개선.html` → `커리어아카이브_v3_백업복원.html`)

- **발견한 문제(테스트·예상·실제):** 제작자가 한 브라우저에서 입력한 경험을 다른 브라우저에서 같은 HTML로 열었을 때, 기존 활동 목록이 보이기를 기대했으나 표시되지 않았다. 현재 기록은 브라우저별 `localStorage`에만 보관되기 때문이다.
- **AI에게 전달한 요청(요지):** 기존 저장 방식과 화면을 유지하면서 JSON 백업 파일을 다운로드하고, 다른 브라우저에서 그 파일을 불러와 경험을 복원하는 기능을 추가하도록 요청했다. 가져오기에 앞서 현재 기록이 교체된다는 안내와 확인창을 표시하고, 올바르지 않은 파일은 거부하도록 요청했다.
- **수정 후 테스트 결과(제작자 직접 확인):** JSON 백업 파일 다운로드, 다른 브라우저에서 JSON 가져오기, 복원한 활동 표시, 새로고침 후 복원 데이터 유지의 **4개 항목이 모두 정상 작동함**을 확인했다.
- **수정 이유:** 기기·브라우저를 변경했을 때 기존 자료가 보이지 않아 경험을 다시 입력해야 하고, 브라우저 데이터가 삭제되면 기록을 잃을 수 있기 때문이다. 이 개선은 수동 이동 기능이며 자동 동기화는 아니다.

### 수정 기록 3 — 면접 질문·답변 세트 관리 및 랜덤 연습 (`커리어아카이브_v3_백업복원.html` → `커리어아카이브_v4_면접연습.html`)

- **발견한 문제(테스트·예상·실제):** 실제 활동의 면접 질문·답변을 입력하며 확인했을 때, 한 경험당 질문과 답변을 각각 하나의 입력란에 작성하는 구조였다. 여러 질문을 질문·답변 단위로 나누어 관리하거나 무작위로 꺼내 연습하는 기능이 없었다. 기대한 사용 방식은 활동별로 질문 세트를 여러 개 저장하고, 질문을 무작위로 보면서 답변을 떠올린 뒤 핵심 답변을 확인하는 것이었다.
- **AI에게 전달한 요청(요지):** 기존 경험 데이터, 디자인과 v3 백업·복원을 유지하면서 경험별 면접 질문·답변 세트를 여러 개 추가·수정·삭제할 수 있도록 하고, `면접 연습` 메뉴에서 활동 제목과 무작위 질문을 표시한 후 버튼을 눌렀을 때 답변 핵심 내용이 나타나도록 요청했다. 기존의 단일 질문·답변도 새 화면에서 계속 보이도록 요청했다.
- **수정 후 테스트 결과:** v4 HTML에 질문 세트 편집, 활동별 질문 목록, 랜덤 질문/답변 보기 기능을 구현하고 JavaScript 문법 검사를 통과했다. 이후 사용자는 전체 체크리스트를 완료했다고 알렸다. 다만 **v4 각 테스트의 구체적인 관찰 결과는 별도로 전달받지 않아**, 세부 항목별 성공 여부를 문서에 임의로 기재하지 않았다.
- **수정 이유:** 한 경험에 대해 여러 질문을 준비해야 하는데 질문과 답변을 한 덩어리로 입력하면 각각을 구분하기 어렵고, 기록을 읽기만 해서는 실전 면접처럼 답변을 떠올리는 연습을 하기 어렵기 때문이다.

> **호환성:** v4는 기존 v3와 같은 브라우저 저장 키를 사용하며, 기존 단일 질문·답변을 새로운 질문 세트로 읽는다. 새 질문 세트는 `qaPairs`에 저장하며, v3 백업 파일을 가져오는 기능도 유지한다. 같은 저장소를 사용하므로 기존 활동을 먼저 JSON으로 백업한 후 테스트하는 것이 안전하다.

## 추가 개선 — 활동별 가로 막대 타임라인 (`v4` → `커리어아카이브_v5_타임라인.html`)

- **개선 요청:** 여러 경험의 시작·종료 시점을 한눈에 비교할 수 있도록 목록 상단에 긴 가로 막대형 타임라인을 추가하고자 했다.
- **반영 내용:** 활동별 기간을 막대로 나타내고, 프로젝트·대외활동·교육을 색상으로 구분했다. 진행 중 활동은 현재까지 표시하며, 막대 클릭으로 상세 화면에 이동하도록 구현했다. 검색·유형 필터도 타임라인과 연결했다.
- **디자인 선택 과정:** 활동 전체를 하나의 통합 타임라인으로 보여주는 v6 시안도 제작했으나, 사용자가 디자인을 비교하고 **활동별 가로 막대형 v5가 더 좋다**고 판단해 v5를 최종 선택했다. 따라서 **v6는 최종 제출 파일이 아니다.**
- **확인 상태:** 사용자가 전체 체크리스트를 완료했다고 알려왔다. 단, 타임라인 표시·상세 이동의 항목별 결과에 관한 구체적인 설명은 아직 없으므로 정량적 성공 사례를 덧붙이지 않는다.

## 사용자 피드백 및 반영 기록

- **의견 제공자와 확인 상황:** 2-2 과제 평가자가 커리어 아카이브의 데이터 보관 방식에 대해 질문했다. 평가자가 페이지에서 수행한 구체적인 작업이나 조작 과정은 확인되지 않아, 아래 내용은 **사용 과정 관찰이 아닌 평가자 질문을 통한 피드백**으로 기록한다.
- **사용자의 행동과 질문:** 평가자는 “다른 컴퓨터에서는 입력한 데이터가 안 보이는 건가요? DB 연결은 안 되어 있나요?”라는 취지로 질문했다. 실제 버튼 클릭이나 작업 수행 순서는 관찰하지 못했다.
- **받은 피드백:** 다른 컴퓨터·브라우저에서 기존 기록을 확인할 수 있는지, 데이터베이스와 연결되어 있는지에 대한 의문이 제기됐다. 이를 통해 현재 `localStorage` 방식의 데이터 이동 한계와 안내 필요성을 다시 확인했다.
- **반영 내용과 결과:** v3에서 JSON **백업·가져오기** 기능을 추가했다. 기존 브라우저에서 기록을 파일로 내려받아 다른 브라우저에서 가져오는 방식으로, 데이터베이스나 서버를 연결한 것은 아니다. 제작자가 직접 백업 파일 다운로드, 다른 브라우저에서 가져오기, 기록 표시, 새로고침 후 유지의 **4개 테스트를 수행하여 모두 성공**했다. 사용자에게는 자동 동기화가 아니라 수동으로 옮기는 방식임을 안내한다.

> **2-3 사용자 테스트 요건 확인:** 위 내용은 실제 평가자 발언에 근거한 피드백 반영 사례이지만, 과제가 요구하는 ‘사용법을 설명하지 않고 다른 사람 1명에게 작업을 수행하게 한 뒤 행동을 관찰한 기록’과는 구분된다. 그런 테스트도 진행했다면 참여자·요청한 작업·관찰 행동과 질문을 실제 사실대로 추가해야 한다. 진행하지 않았다면 위 피드백만으로 해당 요건을 모두 충족했다고 단정할 수 없다.
