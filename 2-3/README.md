1. 미션 소개
직접 만든 페이지는 기능이 어디에 있고 어떻게 사용하는지 이미 알고 있어, 처음 사용하는 사람이 겪을 어려움을 놓치기 쉽습니다. 제작자에게 익숙한 버튼 이름이 다른 사람에게는 모호하거나, 중요한 안내가 눈에 띄지 않을 수도 있습니다. 실제 사용 과정을 관찰하면 어떤 부분을 개선해야 하는지 구체적으로 확인할 수 있습니다.

발견한 문제를 AI에게 전달할 때도 관찰한 내용이 중요합니다. '계산이 이상하다'보다 어떤 값을 입력했고, 어떤 결과를 예상했으며, 실제로 무엇이 표시되었는지 설명하면 수정할 대상을 명확히 할 수 있습니다. 확인하지 않은 원인을 단정하기보다 문제를 다시 재현할 수 있도록 설명하는 연습을 합니다.

수정한 뒤에는 같은 테스트를 반복하여 문제가 해결되었는지 확인해야 합니다. 한 부분을 변경하면서 기존 기능에도 영향을 줄 수 있으므로, 이전에 정상적으로 동작하던 기능도 함께 점검합니다. 수정할 때마다 버전을 나누어 저장하면 변경 전후를 비교하거나 문제가 생겼을 때 이전 상태를 확인할 수 있습니다.

이번 미션에서는 '두 AI로 HTML 만들고 테스트하기'에서 선택한 HTML을 테스트하고, 발견한 문제를 AI에게 설명해 하나씩 수정합니다. 다른 사람 1명의 사용 과정과 피드백을 확인하여 개선에 반영하고, 결과를 다시 테스트합니다. 마지막으로 최종 HTML에 맞게 기획서와 제작검증기록을 정리하여, 기획부터 제작·검증·개선까지의 과정을 완성합니다.

2. 최종 결과물
다음 3가지 산출물을 제출한다. (첨부된 기획서와 제작검증기록 양식을 활용할 수 있다.)

HTML 파일 1개
수정과 사용자 피드백을 반영한 최종 버전이다.
파일 이름은 페이지의 내용에 맞게 정한다.
**기획서.md**
'AI와 함께 HTML 페이지 기획서 작성하기'에서 작성한 기획서를 최종 HTML에 맞게 수정한 문서이다.
**제작검증기록.md**
이전 미션의 두 AI 비교 기록과 테스트 3건
수정 기록 3건
사용자 1명의 피드백과 반영 결과
제작검증기록은 화면 캡처를 포함한 문서 파일이나 PDF로 제출할 수 있다.

3. 과제 목표
이 과제를 마친 후, 학습자는 다음을 수행할 수 있어야 한다.

직접 테스트하여 문제를 발견하고, 추측한 원인 대신 관찰한 현상을 AI에게 설명하여 수정을 요청할 수 있다.
한 번에 하나씩 수정하고 버전별로 저장하며, 기존 기능의 정상 동작 여부를 다시 확인할 수 있다.
사용자의 행동과 피드백을 근거로 페이지를 개선할 수 있다.
기획서를 최종 HTML에 맞게 수정할 수 있다.
4. 기능 요구 사항
다음 요구사항을 모두 만족해야 한다.

수정 내용과 근거 3건 기록
각 수정 건에 다음 4가지를 기록한다.
발견한 문제(테스트 내용·예상 결과·실제 결과)
AI에게 전달한 요청
수정 후 테스트 결과
수정 이유: 문제를 해결하지 않았을 때 사용자가 겪을 불편을 설명한다.
문제는 관찰한 현상을 기준으로 설명하고, 확인하지 않은 원인을 단정하지 않는다.
한 번에 하나씩 수정하고, 수정한 HTML 전체를 받아 페이지_v2.html, 페이지_v3.html처럼 버전별로 저장한다.
수정한 부분과 기존에 정상 동작하던 기능을 다시 테스트한다. 새 대화의 AI에게 검토를 요청할 수 있으나, 지적의 타당성은 직접 확인한다.
이전 미션의 테스트에서 예상과 다른 결과가 있었다면 우선 수정한다.
사용자 1명의 테스트와 피드백 반영
페이지의 대상 사용자 1명에게 사용법을 설명하지 않고 수행할 작업만 제시한다. 대상 사용자를 찾기 어렵다면 동료에게 요청할 수 있다.
다음 4가지를 기록한다. 사용자가 어려움을 겪지 않았다면 그대로 기록하고, 관찰하지 않은 내용을 작성하지 않는다.
테스트 참여자와 요청한 작업
사용자의 행동과 질문
받은 피드백
반영 내용과 결과
피드백 중 1건 이상을 페이지에 반영하고 결과를 기록한다.
최종 기획서 정리와 산출물 제출
수정과 피드백 반영으로 변경된 화면 구성·동작·완료 기준을 기획서에 반영한다.
구현하지 않은 기능은 '추가 기능'으로 분류하고, 비목표 3가지와 검증 방법 1가지가 최종 HTML에 부합하는지 확인한다.
최종 HTML, 기획서.md, 제작검증기록.md를 함께 제출한다.
5. 보너스 과제 (선택)
배경이 다른 사용자에게도 테스트를 요청하고, 사용자들이 겪는 어려움을 비교해 개선에 반영한다.
피드백을 반영한 뒤 사용자에게 다시 테스트를 요청하고, 불편이 줄었는지 확인한다.
페이지를 계속 사용한다면 무엇을 개선하고 관리해야 할지 검토한다.

7. 제약 사항
HTML은 파일 1개로 구성한다. CSS와 필요한 JavaScript를 같은 파일에 포함하고, 평가자가 브라우저에서 열어 기획서의 필수 기능을 확인할 수 있도록 한다.
로그인, API 키, 서버가 필요한 기능과 챗봇·AI 기능은 추가 기능으로 분류하고, 해당 기능 없이도 페이지가 열리고 동작하도록 한다.
사진·글·글꼴·라이브러리 등 외부 자료는 사용 권한을 확인한 뒤 활용한다. 사진은 로컬 파일 대신 https://로 시작하는 인터넷 주소로 삽입한다. 인터넷 주소로 불러오는 자료는 별도로 첨부하지 않으며, 다른 컴퓨터에서도 정상적으로 표시되는지 테스트한다.
