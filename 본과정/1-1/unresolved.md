# 미해결 기록 — 최종 수행자 확인 필요

> **주의:** 과제에서는 실제 프롬프트를 고쳐도 끝내 원하는 결과가 나오지 않은 과업 **2건 이상**과, 각 과업의 **시도한 프롬프트 원문 및 수행자 본인이 직접 쓴 막힌 이유**가 필요하다. 아래는 실제 실험에서 확인된 문제에 기반한 후보로, AI가 대신 미해결 확정이나 개인적인 판단을 작성하지 않았다. 성공한 시도는 미해결로 세면 안 된다.

## 미해결 후보 1 — 상세한 평가와 사실 정확성 동시에 만족시키기

**관찰:** 평가를 항목마다 2~3문장으로 늘리라는 요청 뒤, 근거 없는 '준비 때문에 수업 지연이 없었다', '학생 만족도가 높았다'는 문장이 생성되었다. 근거 없는 내용을 쓰지 말라는 강화 메시지 뒤에는 해당 표현이 사라졌지만 평가 내용이 짧아졌다. Few-shot으로 예시를 제공한 뒤에도 일부 평가 문장은 간략했다.

**실제로 시도한 프롬프트 (원문):**

```text
방금 작성한 수업일지에서 조건을 추가할게.

1. '복습'이라는 소제목은 원본 양식 그대로 유지해. '지난 시간 복습'처럼 변경하면 안 돼.
2. '평가' 아래의 수업 분위기, 이론/실습에 대한 학생들 반응, 수업 난이도, 특이사항, 총평은 각각 2~3문장으로 구체적으로 작성해.
3. 기존에 전달한 수업 내용과 현장 메모는 그대로 유지해.
4. 실제 진행 여부가 확인되지 않은 활동은 추가하지 마.
5. 다른 대제목과 소제목, 항목 순서도 원본 양식 그대로 유지해.

위 조건을 반영하여 수업일지 전체를 다시 작성해 줘.
```

**수행자가 실제로 밝힌 아쉬움:** "그 수업평가쪽이 좀만 더 길면 좋겠다는 생각이 들긴했어."

**막힌 이유(자료로 확인되는 설명):** 평가를 길게 요구하자 근거 없는 문장이 생성되었고, 추측을 금지하자 분량이 다시 줄었다. 이 설명은 대화 관찰을 정리한 것으로, 수행자의 직접 작성 문장으로 대체하지 않는다.

**미해결 상태:** 미해결 후보로 유지. 수행자가 상세함을 아쉬워했으나 제출 기준의 직접 작성 이유·확정 여부는 추가 확인 필요.

## 미해결 후보 2 — Few-shot 예시를 참고하면서 원본 소제목까지 완전히 고정하기

**관찰:** 과거 차시 일지 예시를 반영한 초기 Few-shot 실행에서는 14주 차 빈 양식의 '복습' 대신 '지난 시간 복습'이라는 제목이 출력됐다. 반면 마지막 Few-shot 재실험에서는 '복습'이 유지되었다. **따라서 현재 자료만으로는 이 과업이 '끝내 해결하지 못한' 문제라고 확정할 수 없다.** 이 후보는 미해결로 바로 제출하지 말고 다른 실측 미해결 건을 선택하거나 추가 확인해야 한다.

**실제로 시도한 프롬프트 (원문):**

```text
1. 내가 제공한 14주 차 수업일지 원본 양식의 대제목, 소제목, 항목 순서를 절대 변경하지 마.
2. PPT에 있는 커리큘럼명, 수업 주제, 수업 목표는 원문 그대로 가져와.
3. 앞서 제공한 실제 수업일지 3개의 문체와 평가 작성 방식을 참고해 줘.
```

※ 위 세 줄은 실제 작성 요청의 해당 항목 **발췌**다. 제출 전 시도 프롬프트 전문을 기존 Claude 채팅에서 그대로 복사해 교체해야 한다.

**막힌 이유:** 미해결로 확정되지 않았으므로 작성하지 않음.

**미해결 상태:** 최종 Few-shot 실행에서 소제목 유지에 성공했으므로 미해결로 확정하지 않음. 두 번째 실제 미해결 과업이 아직 확인되지 않음.

## 제출 전 확인

- 실제 미해결 과업 2건을 확정할 것 (현재 2번은 해결된 적 있어 미해결 증거가 부족함).
- 과업마다 시도한 **전문**을 실제 채팅에서 복사하여 붙일 것.
- 과업마다 막힌 이유를 수행자 본인의 언어로 작성할 것.

**수행자 의견(후속 대화):** 평가 상세함 외에는 "진짜 딱히 없었었는데...."라고 답했다. 따라서 확인되지 않은 두 번째 미해결 과업을 만들어 넣지 않는다.
