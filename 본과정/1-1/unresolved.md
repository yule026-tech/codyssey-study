# 4. 미해결 및 수행 중 어려움 기록

> 2026-11-24. 실험 모델 Claude와 프롬프트 설계를 보조한 ChatGPT의 사례를 **구분**한다. 아래 두 사례는 실제 어려움을 경험한 사례이나, 과제 원문이 요구하는 '프롬프트를 고쳐도 끝내 해결되지 않음'의 입증 여부는 각각 다르다. 해결된 일을 미해결로 꾸며 쓰지 않는다. **막힌 이유와 판단은 사용자 피드백을 토대로 AI가 초안으로 작성했으며 사용자 자필로 주장하지 않는다.**

## 과업 1. 강의에 맞는 새로운 ERD의 완전한 생성·해석

**사용 모델:** Claude (사용자 표시 Sonnet 5.5)  
**실험 자료:** 데이터 모델링 PDF p.16~30, 그림 생성 출력  
**원하는 결과:** 강의 Chen 표기법의 모든 핵심 기호와 키·관계 제약을 올바르게 담은 재사용 가능한 연습용 ERD 그림.

### 시도한 프롬프트 원문 ① (v1 채팅)

```text
강의 자료 30페이지와 38페이지의 예시를 참고해서 새로운 E-R 다이어그램을 직접 그림으로 만들어 줘.

1. 개체 4개 이상, 관계 3개 이상을 포함해 줘.
2. Chen 표기법을 사용해 줘.
3. 개체, 속성, 키 속성, 관계, 카디널리티를 그림에 표시해 줘.
4. 완성된 ERD 그림을 먼저 보여 줘.
5. 그 그림을 보고 풀 수 있는 시험문제 5개를 출제해 줘.
6. 문제의 정답과 해설은 공개하지 마.

학생에게 ERD를 그리라고 하는 문제가 아니라, 네가 직접 완성된 ERD 그림을 제시하는 문제로 만들어 줘.
```

### 시도한 프롬프트 원문 ② (v2 채팅)

```text
강의 자료에 나온 Chen 표기법을 사용해서 새로운 ERD 그림을 만들어 줘.

개체 3개 이상과 관계 2개 이상을 포함하고, 약한 개체, 다중 값 속성, 키 속성, 필수적 참여, 약한 개체가 강한 개체와 맺는 관계를 그림에 표시해 줘.

완성된 ERD를 그림으로 보여 줘.
```

### 관찰한 막힘

초기 Mermaid 생성에서는 이중 타원·이중 마름모·이중선이 정확한 형태가 아닌 대체 기호로 나타났고, 키 이름에는 `<u>` 태그가 노출되었다. v2의 새 대학 ERD에서는 대부분의 기호가 올바르게 표현되어 **시각화 문제는 상당 부분 해결**되었다. 하지만 약한 개체 '강좌'의 키를 `(학과번호, 분반번호)`로 정의하면서 그 조합이 유일하다는 업무 규칙을 설명하지 않아, 실제 여러 과목이 같은 분반번호를 사용할 수 있는 상황에서 설계가 모호했다.

**막힌 이유 (AI 정리 초안):** ERD 그림이 보기 좋게 만들어져도 키의 유일성이나 관계 참여 조건이 명확하게 주어지지 않으면 실제 정답으로 써도 되는지 확인하기 어려웠다. 강의 그림의 표기법과 새로운 사례에 대한 설계 가정을 별도로 검증해야 했고, 프롬프트만으로 모든 조건이 자동 보장되지는 않았다.

**최종 상태:** **부분 해결 / 잔여 검증 미완료.** 미해결 후보로는 적합하지만, v2 이후에도 같은 설계 오류가 반복되는지를 확인한 추가 로그는 없다. '끝내 해결 불가가 실증됨'이라고 쓰지 않는다.

## 과업 2. 과제 수행을 돕는 AI가 요청 범위를 오해하거나 과도한 작업을 제안함

**사용 모델:** ChatGPT (GPT-6) — Claude DB Mate 실행 채팅이 아닌 **프롬프트 설계 보조 대화**  
**원하는 결과:** 사용자의 기존 작업을 최대한 유지하면서 필요한 부분만 수정하고, 빠르고 정확하게 과제 완료 절차를 안내함.

### 실제 사용한 프롬프트 원문 ①

```text
아니... 프롬프트 1번만 수정해서 전체 프롬프트 다시 보내줘봐
```

**발생 상황:** 사용자는 기존 공통 프롬프트에서 1번 항목만 바꾸기를 원했지만 ChatGPT는 한때 전체 지시문을 한 문장으로 축소했다. 이후 추가 설명을 받아 원래 2~5번을 유지한 문서로 수정했다.

### 실제 사용한 프롬프트 원문 ②

```text
차라리 저거 말고 30쪽이나 38쪽 처럼 erd 문제 비슷하게 새로운 문제 erd 그림 내달라고 하자ㅏ
```

**발생 상황:** 사용자는 완성된 그림을 보고 푸는 ERD 문제를 원했지만 ChatGPT가 '학생이 직접 그리는 문제'로 안내했다. Claude는 전달된 문구에 따라 상황 설명과 문제를 제공했으므로 Claude의 지시 위반은 아니다. 이후 사용자 요청을 구체화하자 완성된 도서관 ERD가 생성됐다.

### 실제 사용한 프롬프트 원문 ③

```text
dㅡㅁ 근데 v2 넣을때 예시3개랑 이렇게 길게 적나...? v1에서 수정정도 하는거 아니야?? 필요한 부분?
```

**발생 상황:** ChatGPT가 v2에서 처음에는 9개 항목과 Few-shot 예시가 포함된 긴 프롬프트를 작성했고, 사용자는 v1에 필요한 규칙만 더하기를 원했다. 지적 후 규칙 4개를 추가한 간결한 v2로 수정했다.

**막힌 이유 (AI 정리 초안):** 과제 제출을 빨리 마무리해야 하는 상황에서 모델이 '도움이 될 만한 추가 작업'을 너무 많이 제안했다. 특히 '부분만 수정'이나 'AI가 그림을 먼저 제시' 같은 범위를 좁히는 표현을 충분히 우선하지 않아, 사용자가 같은 의도를 여러 차례 다시 설명해야 했다.

**최종 상태:** **개별 사례는 수정되었으나 비효율 반복이 확인됨.** 과제 진행의 어려움을 설명하기에 적합하나, 엄밀한 의미의 '프롬프트 수정 후에도 끝내 실패한 과업'으로 확정하기는 어렵다. 실험 모델이 Claude가 아닌 ChatGPT라는 점도 분리 기록한다.

## 왜 이 기록을 남기는가

'모델의 실패'와 '지시문 자체의 모호함'을 섞으면 원인을 잘못 분석하게 된다. v1에서 발생한 잘못된 그림 표현은 v2에서 개선된 부분을 인정하고, 남아 있는 설계 모호성과 보조 AI의 의도 오해는 별도 사례로 보관했다. 두 사례 모두 실제 문장·관찰 근거가 있으며 만들어 낸 실패는 없다.
