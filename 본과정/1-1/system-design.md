# 2. DB Mate 시스템 설계 문서

> 작성·실험일: 2026-11-24. 시스템 프롬프트 v1→Few-shot→v2 순으로 진행. **실제로 사용한 전문**은 아래 코드블록에 보관했다.

## 1. 타겟 사용자와 업무 문제

대상은 매주 데이터베이스 수업 PPT를 받는 대학생이다. 매주 강의 자료를 요약하고 복습문제를 만드는 반복 작업에 시간이 들고, 새 AI 채팅을 열 때마다 형식과 과목 배경을 재설명해야 한다. 목표는 **강의 파일 업로드 → 핵심 요약 → 예상문제 → 답안 채점·해설**을 일관되게 제공하는 과목 전용 튜터다. 현재 3주차 파일로 검증했지만, 다른 주차 자료에도 재사용하는 설계다.

**입력:** 과목/주차, PPT·PDF 파일, 작업 요청, 난이도·분량·정답 공개 여부.  
**출력:** 주제별 요약, 자료 쪽수 근거, 객관식·주관식·ERD 문제, 사용자 답안 해설.  
**보안:** 수업 공개 자료만 실험에 사용하고 개인정보·API 키·계정 이메일을 저장하지 않는다.

## 3. 실제 시스템 프롬프트 v1 [카테고리: 페르소나]

```text
너는 데이터베이스 과목을 공부하는 대학생을 위한 AI 시험 대비 튜터 'DB Mate'다.

[역할]
업로드된 데이터베이스 강의 자료를 분석하여 학생이 시험을 준비할 수 있도록 돕는다.

[전문 분야]
데이터베이스, 데이터 모델링, 개체-관계 모델, ERD, 관계형 데이터베이스

[말투]
친절하고 이해하기 쉬운 한국어로 설명한다. 어려운 개념은 간단한 예시를 활용한다.

[주요 기능]
1. 강의 자료의 핵심 내용을 요약한다.
2. 강의 내용에 기반한 예상문제를 출제한다.
3. 학생이 제출한 답안을 채점하고 해설한다.
4. 학생이 이해하지 못한 개념을 추가로 설명한다.
5. 사용자가 요청하면 강의 자료의 ERD를 분석한다.

[규칙]
1. 업로드된 강의 자료를 우선적으로 참고한다.
2. 강의 자료에 없는 내용을 임의로 만들어 내지 않는다.
3. 사용자의 요청에 맞는 형식으로 답변한다.
4. 중요한 개념에는 가능한 경우 강의 자료의 페이지 번호를 표시한다.
5. 이전 대화 내용을 참고하여 답변한다.

[우선순위]
1. 강의 내용의 정확성
2. 시험 대비 학습 효과
3. 이해하기 쉬운 설명
4. 답변 형식의 일관성

사용자가 질문하면 위 규칙에 따라 답변한다.
```

## 4. 사용자 프롬프트 (실행에 사용한 예)

```text
이번 강의 자료를 바탕으로 객관식 예상문제 3개를 출제해 줘. 정답과 해설은 내가 답을 제출한 다음에 알려 줘.
```

**범용 사용자 입력 템플릿 [카테고리: 텍스트 생성]**

```text
[DB Mate 학습 요청]
과목: {과목명}
주차: {주차}
강의 자료: {업로드한 PPT 또는 PDF}
요청 작업: {요약 / 예상문제 / 답안 채점 / ERD 해석}
문제 유형 및 수: {예: 객관식 3개, 서술형 2개}
정답 공개: {답안 제출 후 / 즉시}
추가 조건: {분량, 페이지 표기, 난이도 등}
현재 지정한 주차 자료만 근거로 요청을 수행해 줘.
```

위 템플릿은 **재사용을 위해 만든 서식**이다. 이번 실제 실험에서 그대로 전송된 원문은 아니라서 '완성해 실제 사용한 프롬프트 3건'의 산정에서는 제외한다.

## 5. Zero-shot과 Few-shot 비교

- **Zero-shot:** v1에는 대화 예시가 없었다. 동일한 강의 자료의 ERD 기호 정리 요청에 개체·관계·속성·참여 기호 및 페이지 번호를 비교적 정확히 제시했다. 처음에는 외부 용어 '식별 관계'를 자료 용어와 구분하지 않았다.
- **Few-shot:** 새 Claude 채팅에서 v1에 질문·정답 예시 3개를 부가하고 같은 PDF·같은 'ERD 기호 정리' 요청을 입력했다. 개념 정확성은 비슷했으나 외부 용어를 여전히 별도 구분하지 않았고 '시험에 자주 나오는 유형'이라는 근거 없는 표현이 재발했다.
- **차이:** Few-shot은 형식과 응답 패턴의 예시를 제공했지만 이번 1회 시험에서 뚜렷한 정확도 향상은 확인되지 않았다. 아래 세 번째 예시는 모호한 입력에 되묻기를 보여 주지만 그 행동 자체를 별도로 재실행해 검증하지는 않았다.

### Few-shot 예시 3건 (실험에 사용한 원문)

```text
[Few-shot 예시]

아래는 DB Mate가 따라야 할 질문과 답변의 예시다.

예시 1 — 개념 요약
User: 데이터 모델링이 무엇인지 요약해 줘.
AI: 데이터 모델링은 현실 세계의 데이터를 컴퓨터 세계의 데이터베이스로 옮기는 변환 과정입니다. 필요한 데이터를 선별하는 추상화 작업이 포함됩니다. (PDF 2~4페이지)

예시 2 — 예상문제 출제
User: 데이터 모델의 구성 요소에 관한 객관식 문제 1개 내줘.
AI:
문제: 데이터 모델의 구성 요소가 아닌 것은?
① 데이터 구조
② 연산
③ 제약조건
④ 물리적 설계
정답은 답안을 제출한 뒤 공개하겠습니다.

예시 3 — 모호한 입력에 되묻기
User: ERD 문제 내줘.
AI: ERD 그림을 보고 해석하는 문제를 원하시나요, 아니면 상황 설명을 읽고 직접 ERD를 그리는 문제를 원하시나요? 원하는 유형을 알려 주시면 그에 맞게 문제를 출제하겠습니다.

[적용 규칙]
위 예시의 응답 형식과 행동 방식을 참고하되, 실제 답변 내용은 사용자가 업로드한 강의 자료를 기준으로 작성한다.
```

### 단계적 추론 유도 여부

v1과 Few-shot 시험에는 단계별 판단 과정을 출력하도록 요구하는 단계적 추론 프롬프트를 **추가하지 않았다**. v2에도 내부 사고 과정을 공개하라는 문구는 없다. 결과에 필요한 근거(쪽수, 불확실성, 표기법 한계)를 설명하도록 지시하는 검증 중심 전략을 채택했다. 이는 상세한 사고 과정 출력과 구분된다.

## 6. 사전 검증 전략

자료에 없는 날짜·시험 배점·출제 빈도, 그림에 없는 키·관계·참여 조건, 틀린 쪽수, 오래된 주차와 새 주차의 혼합을 사실 오류 후보로 정한다. 평가 기준은 **A(정답+근거)** 또는 **B(모름/확인 필요+확인 절차)** 중 하나를 충족하면 Pass, 둘 다 아니면 Fail이다. 모델 평가자가 직접 확인해야 하는 규칙이라는 점 때문에 아래 판정은 **AI 작성 검토 초안**이다.

### 환각 검증표

| 번호 | 검증 질문/대응 항목 | 자료의 정답 | Claude에서 확인된 내용 | 판정 |
|---|---|---|---|---|
| 1 | 개념적·논리적·물리적 단계 차이 | 무엇/어떤 구조/실제 저장, p.7 | 초기 요약 및 오답 해설에서 정답과 페이지 표시 | **Pass (A)** |
| 2 | 약한 개체의 표기법 | 이중 사각형, p.27 | 첫·두 번째 기호표에서 설명과 쪽수 제시 | **Pass (A)** |
| 3 | 다중 값·유도 속성 표기법 | 이중 타원 p.16 / 점선 타원 p.18 | 두 표현과 근거를 제시 | **Pass (A)** |
| 4 | 필수적 참여 기호 | 이중선 p.26 | 기호표에 이중선과 해당 페이지 제시 | **Pass (A)** |
| 5 | 계층·네트워크 모델의 관계 정의 수 | 하나 p.33 / 여러 개 p.36 | 채점 해설에서 구분과 페이지 제시 | **Pass (A)** |
| 6 | 실제 시험 출제 확률·배점 | 강의 자료에 없음 | v2 시험에서 모른다고 밝히고 공지·기출 확인을 제안 | **Pass (B)** |

1~5번은 기존 대화의 응답을 검증 질문 형태로 재구성한 것이며, **독립 검증 질문 5개를 새로 보낸 로그는 아니다.** 원본 답변과 검증표를 연결해 볼 수 있도록 적었다.

### 별도 오류 / 지점 표시

- **근거 없는 단정:** v1 초기 응답의 '시험 출제 가능성이 가장 높은 파트'와 Few-shot 응답의 '시험에 자주 나오는 유형'은 PPT에 없는 평가였다.
- **표현 한계:** v1 첫 ERD 렌더링에서 밑줄 `<u>` 태그 노출, Chen 표기법의 이중 도형·이중선이 대체형으로 표시됨. AI가 표현 한계를 인정했기 때문에 전부 환각이라고 분류하지 않았다.
- **설계 가정:** v1 ERD에 자료에서 확인되지 않은 일부 참여조건을 선택적 참여로 설정했다고 설명했다.
- **v2 첫 응답:** 새 채팅에서 v2에 없었던 'ERD 문제 서술형 3개' 조건을 언급했다. 다른 프로젝트·메모리·입력 영향을 확인할 수 없으므로 원인 미확정, 문맥 끊김으로 단정하지 않았다.

## 8. v1→v2 변경 이력 (변경 규칙 4개)

| 규칙 | 실제 문제 | 수정 이유 |
|---|---|---|
| 6. 실제 시험 출제 예측 금지 | 시험 출제 가능성/빈도 근거 없는 언급 | 알 수 없는 시험 정보를 사실처럼 말하지 않도록 함 |
| 7. ERD 표기법 및 대체 표시 | v1 Mermaid의 밑줄 태그 노출, 이중 기호 표현 실패 | 표기 방식의 한계를 명시하고 강의 표기법 우선 |
| 8. 외부 용어 구분 | '식별 관계'를 자료 사용 용어인 것처럼 사용 | 자료 중심의 시험 공부를 위해 외부 용어 표시 |
| 9. 모호한 ERD 문제 요청 되묻기 | 완성 그림 문제와 학생이 그리는 문제 구별이 어려웠음 | 요청 주체·결과 형태를 명확히 하도록 함 |

**v2 실행 결과:** 대학 ERD에서는 이중 마름모·이중 타원·밑줄을 전보다 정확하게 표현했다. 실제 시험 확률 요청에 대해 모른다고 하고 공지·기출 확인을 제안했다. 다만 강좌 `(학과번호, 분반번호)`의 유일성 가정이 명시되지 않았고, '속성 파트가 가장 많은 페이지'라는 분량 비교는 14~20쪽(7쪽)과 관계 파트 21~28쪽(8쪽)을 단순 비교하면 부정확했다.
